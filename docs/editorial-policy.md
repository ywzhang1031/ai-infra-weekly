# 编辑流程与证据标准

AI Infra Weekly 是中文系统研究周刊，面向推理框架、训练系统和性能工程。网站及稿件公开；个人学习记录、求职材料、原始会话和账户数据不进入本仓库。

## 选题

约 60% 推理框架与性能工程、30% 训练与底层优化、最多 10% 相邻 Infra，比例用于指导，不按条数凑数。优先一手论文、官方仓库和实现文章。只在主要贡献是系统机制或效率改进时纳入 Agent/RL；排除产品宣传、提示词清单与纯模型榜单。

默认每周一发布，窗口为过去 7 天；来源异常时最多扩至 10 天，并写清原因。旧稿不会因重新部署变成新期。

## 从候选到公开稿

1. 依据 `config/sources.json` 收集候选，按原始发布日期、canonical URL、arXiv ID 与标题去重。
2. 检查来源健康与缺口。解析器零条目、被限流或采集上限不代表没有相关工作。
3. 阅读完整原文，区分问题、机制、取舍、硬件、模型、精度、负载、基线、指标与局限。摘要只用于初筛。
4. 保留未知项并明确写“未从来源确认”。未运行复现就不能声称已复现；阅读建议不能写成个人工程成果。
5. 整理为 `content/YYYY-MM-DD.json`，重点通常不超过 3 篇，关注条目可少于目标。来源链接保持 HTTPS；窗口外延伸材料明确标记。
6. `npm run check` 验证公开数据、链接与订阅产物，检查手机布局后发布。只有线上内容与本地产物一致才确认上线并继续订阅通知。

本仓库提供公开稿、来源配置、编辑规范以及站点构建和发布工具。个人研究环境的采集缓存、证据附件和自动化会话不包含在仓库中；在这里构建网站无需调用模型 API。

## 勘误与贡献

通过 Issue 或 Pull Request 说明期号、原文 URL、错误位置和修正证据。勘误保留原期号与 RSS GUID；必要时在稿件摘要或局限字段注明修正，不把旧期重新标为新刊。

现有稿件为 AI 辅助整理。维护者审核投稿与证据后合并；不要声称每项来源结果经过独立实验验证。
